# API reference

Interactive OpenAPI documentation is generated by FastAPI at **`http://localhost:8000/docs`**
(raw schema: `/openapi.json`). This page summarises the endpoints and their rules.

All endpoints except `/api/auth/login`, `/api/meta` and `/api/health` need
`Authorization: Bearer <token>`. Roles are checked on the server. Add `X-Developer-Mode: 1`
to receive the execution `trace` inside the response body.

Errors use `{"detail": {"code": "...", "message": "..."}}`. Validation errors (422) also carry
`errors: [{field, message, type}]`.

## Auth and metadata

| Method | Path | Role | Notes |
|---|---|---|---|
| POST | `/api/auth/login` | — | `{email, password}` → `{token, user}`. Demo password `demo1234`. |
| GET | `/api/auth/me` | any | Current user. |
| GET | `/api/meta` | — | Banner, today (Kolkata), categories, localities, AI mode. |
| GET | `/api/health` | — | 200 when DB + model are ready, 503 otherwise. |

## Customer

| Method | Path | Notes |
|---|---|---|
| POST | `/api/requests/interpret` | `{text, overrides?, mode?: auto\|rules\|llm}` → `extraction` (fields with `source`/`evidence`, `missing_fields`, `questions`, `notes`, `safety_notice`), `ready`, and `search` when nothing is missing. |
| POST | `/api/technicians/search` | `{category, locality, preferred_date, time_window}` → technicians with `match_reasons`, `slots`, `visiting_charge_inr`. |
| POST | `/api/bookings` | Header **`Idempotency-Key`** required. Body `{slot_id, technician_id, category, locality, issue_description}`. 201 → `{booking, replayed}`. 409 `slot_taken` → `alternatives`. 409 `idempotency_key_reused`. 422 rule violations. |
| GET | `/api/bookings/mine` | Own bookings with status history. |
| GET | `/api/bookings/{id}` | Visible to its customer, its technician, or admin; others get 404. |
| POST | `/api/bookings/{id}/cancel` | Allowed until 2 h before the visit (demo policy). |
| POST | `/api/policy/ask` | `{question}` → `mode` (`llm`, `retrieval_only`, `abstained`, `structured`), `route`, `answer`, `citations` [{title, version, section}], `passages`, `safety_notice`, `diy_notice`. |

Example:

```bash
TOKEN=$(curl -s localhost:8000/api/auth/login -H 'content-type: application/json' \
  -d '{"email":"asha@demo.servicesaathi.local","password":"demo1234"}' | python -c 'import sys,json;print(json.load(sys.stdin)["token"])')
curl -s localhost:8000/api/requests/interpret -H "authorization: Bearer $TOKEN" -H 'content-type: application/json' \
  -d '{"text":"My kitchen tap is leaking. I need a plumber tomorrow morning in Wakad."}'
```

## Provider

| Method | Path | Notes |
|---|---|---|
| GET | `/api/provider/me` | Own technician profile. |
| GET | `/api/provider/bookings` | Only bookings assigned to this technician, with `allowed_transitions`. |
| POST | `/api/provider/bookings/{id}/status` | `{to_status, reason}`; confirmed → en_route → in_progress → completed; cancel by provider before work starts. |
| GET / POST | `/api/provider/slots` | List future slots / add `{date, hour}` (one-hour, next 7 days). |
| PATCH / DELETE | `/api/provider/slots/{id}` | Move / remove. 409 `slot_locked` if an active booking exists (also blocked by a DB trigger). |

## Admin

| Method | Path | Notes |
|---|---|---|
| GET / POST / PUT | `/api/admin/technicians[/{id}]` | Charges per category, localities, active flag. |
| GET / PUT | `/api/admin/categories[/{code}]` | Names and descriptions; codes are fixed to the trained model's labels. |
| GET / POST | `/api/admin/localities` | Add a locality (extraction picks it up from the DB). |
| GET / POST | `/api/admin/documents` | Multipart upload of `.md` / `.txt` → new draft version. |
| POST | `/api/admin/documents/{id}/ingest` | Chunk + embed; on success activates this version and supersedes the old one. |
| GET | `/api/admin/documents/{id}/chunks` | Chunks with quarantine flags. |
| GET | `/api/admin/bookings`, `/model-versions`, `/evaluations`, `/audit` | Inspection. |
| POST | `/api/admin/reset` | `{confirm: "RESET"}` restores demo data. |

## Learning Lab and Developer Mode

| Method | Path | Notes |
|---|---|---|
| GET / POST | `/api/labs/sql/queries`, `/api/labs/sql/run` | Fixed catalogue only, READ ONLY transaction, 2 s timeout. |
| POST / GET | `/api/labs/ml/predict`, `/api/labs/ml/report` | Scores, baseline, top features; saved training report. |
| POST | `/api/labs/extraction` | Rules vs LLM side by side (LLM only if configured). |
| GET / POST | `/api/labs/rag/chunks`, `/api/labs/rag/query` | All chunks; retrieval with scores + answer + trace. |
| POST | `/api/labs/booking-race` | Two real concurrent bookings of one slot; returns DB rows; cleans up. |
| GET / POST | `/api/labs/evaluations`, `/api/labs/evaluations/run` | Latest stored runs; run a suite. |
| GET | `/api/labs/deployment` | Which env vars are set (never secret values), migration, model. |
| GET | `/api/dev/scenarios`, `/api/dev/traces`, `/api/dev/traces/{request_id}` | Replay scenarios; traces visible only to their owner or admins. |
